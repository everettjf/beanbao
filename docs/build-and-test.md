## November 2 uncertain mutation recovery

An Agent 0.3.98 live research run requested at least ten cited sources. It returned a readable PDF, but its journal also contained three `report_compose` operations marked `needsReconciliation` from earlier failed proposals, while the overall phase was incorrectly `completed`. Agent 0.3.99 now distinguishes validation errors proven to occur before a named tool's write from unknown write outcomes. The former are recorded as `failed` and can be corrected by the model; a pending or uncertain mutation blocks every later tool call and final completion, even with different arguments. Loading an older inconsistent record and listing it in Sessions reports `needsReconciliation`, rather than silently treating it as complete. Swift and native tests cover safe retry, cross-argument bypass, old-record repair, and a scripted Palmino loop that first sends invalid report arguments and then succeeds. The final release build passed 73 Swift Harness tests, native and browser checks, and the four-package audit. Agent 0.3.99 was installed without a SpringBoard reload; `verify_device.py --expect-bundle` confirmed all four versions, a responsive Bridge, and the phone unlocked with its screen on. The old session now displays `needsReconciliation`. A new run of the same text request completed five `web_search` steps, `report_compose`, and `pdf_render` with no unresolved operation. The previously generated PDF remains on the phone for inspection; its old session needs review because the earlier journal cannot prove those writes were harmless.
