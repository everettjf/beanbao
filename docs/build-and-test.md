# Build and device test record

Updated November 1, 2026. Target: iPhone 11, iOS 26.0.1, Relaxin 0.5.5, RootHide. Historical detailed Chinese-language logs are available in Git history through commit `b55e882`. This file records the current release candidate and subsequent development evidence.

## November 1 overlay voice development

Bridge 0.2.5 displayed the quick input panel above Maps; its keyboard Dictation experiment was rejected as the voice architecture. Bridge 0.2.6 source removes that trigger and is built but not installed. App 0.3.22 adds the `audio` background mode and is installed on the phone. Its package build passed, and after starting a recording in BeanBao, the audio file grew from 284,234 to 674,378 bytes over five seconds while Maps was foreground. The phone remained unlocked; no SpringBoard reload was used for this app update. A real spoken transcript and automatic microphone start from the overlay remain unverified. See [the overlay plan](quick-overlay-prototype.md).

Bridge 0.2.7 / App 0.3.23 implemented a session-bound overlay voice prototype. Both packages were installed on the phone. An authenticated `show_voice` command displayed the panel above Settings and launched BeanBao, but no recording-ready marker appeared before the eight-second timeout. Repeating after killing the app process had the same result. Bridge 0.2.8 / App 0.3.24 extended the startup and recording windows and polled for a pending voice session while the app was active. Both updated packages built, passed the Bridge package audit and native policy tests, and were installed on the phone. On the unlocked phone, that pair displayed the panel above Settings, started the microphone, showed `Listening…`, restored Settings behind the panel, automatically stopped after silence, and returned the `No speech recognized` result to the overlay.

A real spoken sample was then captured through the overlay. The owner said “Open Contacts” twice, and Apple transcription returned `Open contacts open contacts` to the editable field. The old Agent rejected that complete utterance; typing the exact `Open Contacts` phrase in the overlay and tapping Run completed and independently opened Contacts. Agent 0.3.59 now sends noncanonical requests to the selected model for intent classification, accepts only one validated canonical task, and keeps the existing execution allowlist. On the phone, the repeated Contacts request completed from the CLI on Agent 0.3.59 and from overlay Run on its 0.3.58 predecessor. `Open Maps and send a message` and `Open Settings and turn off Wi-Fi` remained rejected. Natural Maps search and note creation requests were classified into their respective bounded workflows, but those executions stopped on later UI safety checks; they are not counted as successful end-to-end tasks. App 0.3.27 discloses request-text model use in Model settings and changes the shortcut hint. No SpringBoard reload was used for the Agent and App-only updates. Bridge 0.2.9 routes the physical Volume Down triple press to the overlay voice session; it was built, audited, and installed with one SpringBoard reload. Physical triple-press acceptance is pending.

The first real triple press on Bridge 0.2.9 opened the overlay above Settings, but it stayed at microphone startup and timed out without a recording-ready marker. The same voice-session route started recording when triggered by the authenticated `show_voice` command, including after terminating the BeanBao app for a cold-start test. Bridge 0.2.10 delays launch until 350 ms after the volume-button release to avoid overlapping the hardware event and LaunchServices transition. Its package built, passed the Bridge audit, and was installed with one SpringBoard reload. On that installed build, an authenticated `show_voice` request displayed **Listening…** above Settings, with the microphone indicator active; closing the overlay removed the indicator. This verifies the voice-session route but not the physical button timing, which still needs a real triple-press retest.

The owner reported that the 0.2.10 physical shortcut felt slow, the overlay could appear more than once, and its high placement was hard to reach. Bridge 0.2.11 adds a three-second trigger cooldown, rejects a new voice session while the overlay is already visible, positions the panel above the keyboard or bottom safe area, and moves LaunchServices calls to a serial background queue so the panel's main thread stays responsive. The package built, passed the Bridge audit, and was installed with one SpringBoard reload. On the unlocked phone, authenticated `show_voice` returned promptly, displayed **Listening…** in a bottom panel over Settings, and the Close button responded to a device tap. Authenticated `show` moved the panel above the on-screen keyboard with its Run button visible. Physical button behavior still requires a real triple-press retest.

The owner then confirmed a real 0.2.11 triple press opened exactly one panel and automatically entered **Listening…**. The owner noticed the background briefly switched from Settings to BeanBao and back. In that session the Agent later recorded a completed Contacts task, but independent foreground observation showed Settings, indicating a late asynchronous restoration could cover the target app. Bridge 0.2.12 keeps a local snapshot of the original screen behind the panel during voice capture and queues Agent start after restoration of the original app. Its package built, passed the Bridge audit, and was installed with one SpringBoard reload. On the unlocked phone, authenticated `show_voice` displayed the overlay with Settings still visible behind it. After the silent recording timed out, entering **Open Contacts** in the overlay and tapping Run completed the Agent task; independent observations showed Contacts in the foreground for seven checks spanning over 12 seconds. This confirms the foreground race is fixed for that path. The owner subsequently reported that the physical triple-press test was entirely normal, including one panel, automatic listening, no BeanBao background flash, and Contacts as the final app. Independent Agent status still showed the task ID from the manual typed test, so a new spoken Run task has not yet been corroborated by device records. The phone was locked when we tried to establish a new starting app, without a SpringBoard reload or lock command in that interval.

## Earlier English build

Bridge 0.2.4 / Agent 0.3.56 / App 0.3.21 were the first English release and UI update. Intermediate English builds were installed and tested on the connected phone. The app, model settings, status and error messages, permission descriptions, release archive instructions, and default command examples are in English. English typed requests are normalized into the same restricted internal task set; legacy Chinese requests remain accepted. Speech is configured for `en-US` dictation; a later build captured a real spoken sample as described above.

`sh scripts/test_native_policy.sh` passed. It covers the allowlist, English command normalization, rejection of compound requests, map and note action policy, OpenAI Chat Completions request/response handling, image placement, HTTPS endpoint validation, and fixed error messages. The content-free Activity parser test, all 8 Python tests, and 18 Swift Harness tests passed. `scripts/build_packages.sh` audited the three packages for dependency chain, content boundaries, mobile service identity, icons, arm64e architecture, signatures, and absence of maintainer scripts.

`scripts/verify_device.py --expect-bundle` confirmed the installed package versions, a running Agent, a responsive Bridge, and an unlocked phone with its screen on. On the intermediate English build, `scripts/accept_text_device.py` ran **Open Settings**, **Open Contacts**, **Open Notes**, **Open Maps**, and **Please open Maps.** Each returned `done` with the correct independently observed foreground bundle ID. **Open Maps and send a message** was rejected before a new task started. The Agent 0.3.56 / App 0.3.19 build kept the same normalization and text harness. Its app-level acceptance passed on the connected phone: **Open Contacts** reached the Contacts foreground; **Create note: BeanBao test 148a8028** created a uniquely titled note and verified it in Notes; **Search Maps for Golden Gate Bridge** showed both a place card and map marker; and **Open Maps and send a message** was rejected without starting a task. The Maps regression test covers a recent-place row matching the query while the actual search field is empty. That device check confirmed Bridge 0.2.4, Agent 0.3.56, App 0.3.19, a running Agent, and an unlocked, responsive Bridge. App 0.3.21 changes presentation and reads the existing audit; it does not change task execution or the Agent protocol. On App 0.3.21, the app-control acceptance again passed **Open Contacts**, a uniquely titled test note, **Search Maps for Golden Gate Bridge** with a verified marker and place card, and rejection of a compound request. `verify_device.py --expect-bundle` confirmed App 0.3.21 installed with Bridge and Agent healthy.

The earlier English home and Model services screens were inspected from real device screenshots on an intermediate build. Home shows English quick actions and status. Model services shows Claude, OpenAI, and Compatible API, with the saved-key state in English. App 0.3.21 puts the composer first, adds a recent Activity preview and a full Activity screen, and uses short status labels. It was installed on the phone; real screenshots confirmed that the Activity view reads the private audit and displays completed and incomplete task summaries without request text. The optional key placeholder is shorter and the privacy note has better contrast. The screenshots used for review are local diagnostic files, not part of the release archive.

## Previous release candidate and independent operation

Bridge 0.2.4 / Agent 0.3.52 / App 0.3.15 passed native policy, 8 Python tests, 18 Swift Harness tests, and package audit. On the unlocked phone, five Chinese text-open commands reached the correct foreground apps; app controls created a unique test note and searched Golden Gate Bridge using Claude. The note title and Maps marker plus place card were independently checked. A forbidden compound task was rejected. Model settings switched and saved all three providers without saving a test key; the temporary compatible API endpoint was removed and Claude restored. The private settings file was owned by mobile with mode `0600`. OpenAI and compatible services still lack live tests with their own keys.

An earlier build (Bridge 0.2.4 / Agent 0.3.49 / App 0.3.12) passed one physical USB-disconnect test: the owner unplugged USB, ran **Open Settings** in BeanBao, and reconnected. The Agent task ID had advanced, its audit had start and completion events, and independent Bridge observation showed Settings in the foreground. This demonstrates one phone-only task, but does not prove every version or task works unplugged.

Earlier supervised tests established that Claude could complete several Maps searches, including Golden Gate Bridge, San Francisco City Hall, California Academy of Sciences, and additional landmarks, while requiring matching map results and cards before reporting success. A map UI change or uncertain result can stop a task. The fixed note flow returns to the Notes list and checks the complete new title before reporting success. A service restart and cancellation were tested on an earlier build. These observations do not imply reliable success for every place or UI state.
